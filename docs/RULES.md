# 架构规则与定位边界（v0.2 · 已确认）

> 本文档汇总自历次架构讨论达成的共识，按 "定位级别" 分级。
> **定位级别含义**
>
> ：
> `硬约束`
>
> ：违反即架构失效，必须无条件遵守
> `强约定`
>
> ：默认遵守，偏离需在评审中说明理由并获得同意
> `默认`
>
> ：无特别理由即按此执行

> **确认记录（2026-10-14）**：用户确认全部 27 条规则通过；**R12 锁定 = 双端统一 QuickJS**（确保最终表达一致）；**P0 端序 = 先做 iOS**；最小闭环 bundle id 使用全新未用过的标识，避免影响已安装程序。

## A. 架构定位（6 条）



| #  | 规则                                                                                                                  | 定位  |
| -- | ------------------------------------------------------------------------------------------------------------------- | --- |
| R1 | **总路线**：Vue 开发体验 → IR 描述文件 → 原生源码（Compose/SwiftUI）——"静态生成原生源码" 路线，非运行时壳（非 WebView 套壳、非 RN 运行时壳）                     | 硬约束 |
| R2 | **产物无 WebView**：UI 100% 原生控件；业务逻辑由内嵌 JS 引擎（QuickJS/JSC）执行 —— 是 "脚本化原生"（RN 模型），不是 "混合 WebView"（Cordova/Capacitor 模型） | 硬约束 |
| R3 | **宿主范围封闭**：仅 Android（Compose）+ iOS（SwiftUI）两个同构原生端，不扩展到小程序 / H5 / 鸿蒙等其他宿主                                           | 硬约束 |
| R4 | **产物独立性**：最终产物为标准原生工程（Xcode 工程 / Gradle 工程），可脱离 Vue/Node 独立编译、运行、上架；Vue 仅是开发期 DSL（编译输入），产物中零 Vue 依赖                 | 硬约束 |
| R5 | **激进路线需先验证**："静态生成原生源码" 在业界无主流先例（Taro/RN/Flutter 均为运行时路线），必须先通过最小闭环证明 "IR → 原生源码 → 独立编译运行" 成立，不得默认可行                | 强约定 |
| R6 | **私有框架定位**：服务本项目（自身 App）的持续迭代，是 "Taro 思路的私有化瘦身版"，不是通用跨端框架                                                           | 硬约束 |

## B. 逻辑处理（6 条）



| #   | 规则                                                                                                    | 定位                |

| R11 | **自动降级路由 + 逃逸阀**：静态分析对可疑复杂度自动降级（编译期 warning 或改走协议桩）；任一端实现不了 → 运行时显式报 `cap not implemented`，绝不静默返回错误结果 | 强约定               |

## H. 解释器布局语义（R30–R37，2026-10-15 拍板）

> 针对「div 高度表达不一致」「flex gap 在 iOS 丢失」两个解释器问题的规则定位。落地：`schema.ts`(sourceTag) + `vue2ir.ts`(template 标记) + `swiftui.ts`(Ctx: definiteHeight/inheritGap/warnings + 降级) + `gen-ios.ts`(告警打印)。

| #   | 规则                                                                                                                                                                                                                                   | 定位    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------- |
| R30 | **高度默认 auto**：无 `height` / `flex` / `align-items:stretch` 的容器不生成任何高度约束，SwiftUI 内容自适应 = CSS 内容决定（div 高度由子内容撑开）                                                                                                   | 硬约束   |
| R31 | **显式 height = border-box**：`height:Npx` 含 padding（CSS 默认 box-sizing），生成时 padding 修饰前置、`.frame(height:)` 后置，frame 限定总视觉高                                                                                                       | 硬约束   |
| R32 | **flex:1 需确定高度**：column 容器的 `flex:1` 子项生成 `.frame(maxHeight:.infinity)` 前，父容器高度必须确定（数字 height / 向上确定的 flex 链 / root 撑满屏）；否则**降级为内容高 + 编译告警**（CSS：父 auto 时 flex-grow 无剩余空间可分配）。row 容器 flex 撑宽度恒有效 | 强约定（已确认） |
| R33 | **justify-content 降级仅限 column**：column 容器的 `center`/`spaceBetween` 弹性分配仅当容器高度确定时生成 Spacer，否则降级 + 告警（CSS：auto 高容器无剩余空间）；**row 容器（水平分配）宽度恒确定，永不降级**                                                        | 强约定（已确认） |
| R34 | **row 交叉轴 stretch 需确定高度**：`align-items:stretch` 子项 `.frame(maxHeight:.infinity)` 仅当 row 容器高度确定，否则降级 + 告警；column 子项填满父宽（div block）不受限                                                                              | 强约定（已确认） |
| R35 | **gap 只作用于渲染兄弟**：`v-if` 条件块是逻辑层不参与布局；gap→spacing 仅施加于实际渲染的相邻兄弟之间（SwiftUI VStack/HStack spacing 单子项容器无视觉）                                                                                                    | 硬约束   |
| R36 | **gap 透传仅限 `<template>`**：父容器全部子项均为 `<template>` 来源的 condition（同一渲染层，如多 tab 分支）时，父 gap 透传为其内部容器的 spacing（`<template>` 在 CSS 中透明、不产生盒子）；**`<div v-if>` 等真实元素不透传**（父 gap 只作用于盒子与兄弟之间，其内部间距由自身 gap 决定） | 硬约束（已确认） |
| R37 | **混合子项不透传**：父容器子项混有真实元素与 `<template>` condition 时 gap 不透传（父 gap 作用于真实盒子之间），由 R35 兜底                                                                                                                             | 强约定   |
| R38 | **margin 用包装容器表达**（R-H6）：`margin-top` / `margin-top:auto` / `margin-left:auto` 不生成独立兄弟占位（Color.clear/Spacer 会被 VStack(spacing) 前后各计一次 spacing，与 gap 叠加双计——实测 gap16+margin16 被算成 48pt）；改用透明包装 `VStack{child}.padding(.top,N)` / `VStack{Spacer;child}` / `HStack{Spacer;child}`，间距只叠加一次 gap，与 CSS（gap + margin）一致 | 硬约束 |
| R39 | **flex 伸缩与滚动（2026-10-15）**：`flex-grow:N` → IR `flex:N`（弹性占比）；`flex-shrink:0` 语义 iOS 默认满足（flex:1 生成 `.frame(maxHeight:.infinity)` 天然不压缩，不映射 IR）；`overflow:auto` → 节点升级为 `scroll`（生成 ScrollView，占满剩余空间、内容可滚动，配合 flex 实现「上部内容伸缩滚动 + 底部固定」）；`height:100%` → `flex:1`（父高度确定链上撑满，root 撑满屏场景与 CSS 等价）；`height:'fill'` 视为确定高度（R-H3 判定链） | 硬约束 |
| R40 | **组件内联展开（2026-10-15）**：`components/*.vue`（PascalCase 文件名）注册为组件表；自定义标签（精确名 + kebab→Pascal 兜底）查表后**编译期内联展开**组件 template，输出仍为单棵 IR 树（codegen 零改动）。规则：① props 仅支持静态 attr（`value="x"`）与 `:bind` 字面量（`'str'`/数字/bool），组件内 `{{ prop }}` 编译期替换为字面量；② 非常量绑定（`:x="state"`）→ warning 忽略该绑定，组件内若引用该 prop → 编译报错；③ 样式作用域 = 组件类优先 + 页面全局兜底（同名类组件覆盖，约定组件类名前缀，无 scoped hash）；④ 组件 `<script setup>` 仅允许 import/defineProps，其余逻辑 → warning（纯展示组件阶段）；⑤ 组件需单根元素；⑥ 注意：@vue/compiler-sfc `parse` 对相同 source+filename 返回**共享 AST**，插值替换必须深拷贝（structuredClone），否则污染后续解析 | 硬约束（已由 R41 取代） |
| R44 | **padding 链 / 胶囊标签抽离（2026-10-15）**：① padding：theme 模式下 4 边齐全 → 单次 `.pad(top:right:bottom:left:)`（等价 `padding(EdgeInsets(top:leading:bottom:trailing:)` 一次内缩，视觉与 4 段链一致）；4 边全等 → `.padding(v)`；≥2 边部分 → `.pad(仅存在的边)`；单边保留原 `.padding(.top, n)` 短表达式；无 theme 回退 4 段链。② 胶囊标签：检测条件=radius≥90 且 background/borderColor **rgb 一致** 且 padding 上下/左右对称 → 单次 `.tagCapsule(color, radius:, bg:, stroke:, h:, v:)`（展开等价 padding(h,v)+background(color.opacity(bg))+cornerRadius(radius)+overlay stroke）；基色只取 rgb 的 Theme 名，alpha 拆为参数避免双重 `.opacity`；条件不满足（异色、非对称、小圆角）→ 不抽离保持原样 | 硬约束 |
| R43 | **frame 组合抽离（View 扩展，2026-10-15）**：高频 `frame(maxWidth/maxHeight/minWidth/minHeight .infinity)` 组合抽为 `extension View` 方法（Theme.swift 内），生成代码改为短调用。规则：① 映射表——`fillW()`=frame(maxWidth:.infinity)、`fillW(_ align)`=frame(maxWidth:.infinity, alignment:)、`fillW0()`=frame(minWidth:0, maxWidth:.infinity)、`fillH()`/`fillH(_ align)`=frame(maxHeight…)、`fillH0()`=frame(minHeight:0, maxHeight:.infinity)、`fillAll()`=frame(maxWidth:.infinity, maxHeight:.infinity, alignment:.topLeading)；② 数字 width/height 的 `.frame(width:)/.frame(height:)` 与 root ZStack 双轴 fill（默认 center 对齐，语义与 fillAll 不同）保留内联；③ theme 模式启用（`currentFrameShort`），无 theme 回退内联保持兼容；④ 方法默认参数 `_ align: Alignment = .center`（fillW/fillH），调用 `.fillW(.leading)`；⑤ generateThemeSource 恒附 View 扩展，页面与组件共享 | 硬约束 |
| R42 | **样式 Token 抽离（Theme.swift，2026-10-15）**：编译期收集页面 + 全部组件树的**颜色与字体组合**，去重后生成 `Theme.swift`（`enum Theme`：颜色 `static let cf3dca0 = Color(red: 243/255.0, …)`、字体 `static let fs17b = Font.system(size: 17, weight: .bold)`），生成 Swift 代码中的颜色/字体改为 `Theme.<name>` 引用。规则：① 颜色命名=语义表（black/white/red/green/blue/yellow/orange/pink/purple/brown/gray/silver 等 12 基本色）匹配则语义名，否则 `c<hex>`（如 `cf3dca0`）；同 hex 不同 alpha → 共享基色常量 + 使用点 `.opacity(a)`；② 字体命名 `fs<size><w>`（size 小数点→`_`，w=r/m/b），含默认组合（text fs15r、button fs15m）；③ 收集范围=background/color/borderColor/colorActive 与 text/button 的 fontSize+fontWeight；④ 未传 theme（回退）→ 保持旧 `Color(red:…)` 内联，保证既有调用兼容；⑤ gen-ios 统一 `collectTheme(screen.ui, ...components)` → `buildTheme` → 传 `generateScreenSource/generateComponentSource` → 写 `Theme.swift`（页面与组件共享同一色板，xcodegen 目录 glob 收编） | 硬约束 |
| R41 | **组件独立原生 View（2026-10-15）**：组件不再内联展开——每个 `components/Xxx.vue` 生成**独立 Swift 文件** `XxxView.swift`（`struct XxxView: View`，props 为 `let p: String` 属性），页面使用点生成 `component` IR 节点 → `XxxView(attrs)` 引用调用。规则：① **组件树独立构建**：组件样式独立作用域（不合并页面全局）；`{{ prop }}`（任意名，隐式 prop，不强制 defineProps）→ `text` 节点 `props.ref` → Swift `Text(prop)`；纯单插值可整体 ref，插值混合文本（`{{a}} 字`）→ 编译报错；② **组件根布局 props 剥离提升**：组件根 `flex/width/marginTop/marginTopAuto/marginLeftAuto` 不进入 View 内部（View 大小=内容），剥离后由使用点 `component` 节点承载（`StatCellView(...).frame(minWidth:0, maxWidth:.infinity)`）；③ **使用点校验**：attrs 键不在 defineProps → warning「未声明」；defineProps ∪ 组件树实际引用（collectRefs）未全部传入 → warning「Swift 编译缺参」；④ 非常量绑定 → warning 忽略；⑤ 组件内再引用组件（嵌套）→ R13 报错（本轮不支持嵌套）；⑥ 组件 props 字面量类型 string/number/boolean，Swift 参数统一字符串化（`let p: String`）；⑦ codegen：`generateComponentSource` 输出独立 View 文件，`component` case 输出 `NameView(args)` + 位置修饰；gen-ios 写 `XxxView.swift`（xcodegen sources 目录 glob 自动收编） | 硬约束 |
