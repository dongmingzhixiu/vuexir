## 真机构建暴露并修复（Gradle Kotlin 编译，而非静态审查发现）

| # | 问题 | 修复 |
|---|------|------|
| A18 | `component` 分支拼接 modifier 时**未过滤空串也未补 `Modifier` 前缀**（`flexModifier` 无 flex 返回 `''`）：`['', 'Modifier.clickable {…}']` → 输出 `modifier = .clickable {…}`（前导点）→ Kotlin 语法错误，全部 tab 页编译失败 | 抽出统一 `R-MODCHAIN`：过滤空串 + 复原 `Modifier.` 前缀（`modifier = Modifier.clickable {…}`） |
| A19 | 图标弃用告警：`Icons.Filled.MenuBook` / `Icons.Filled.AltRoute` 在 Material3 已弃用 | ICON_MAP 改 `Icons.AutoMirrored.Filled.*` + 导入 `androidx.compose.material.icons.automirrored.filled.*` |
| A20 | **详情页顶部空档 ≈ 2 个系统栏高**（用户真机反馈）：外层 `Scaffold` 未设 `contentWindowInsets`，即使 detail 路由没有 topBar，它仍按默认 insets 给内容留一次状态栏内边距；内层详情 `Scaffold` + `TopAppBar` 又算一次 → 叠加 | 当时加 `contentWindowInsets = WindowInsets(0, 0, 0, 0)`；**该外层 Scaffold 已在 A21 中整体移除，问题由结构消除** |
| A21 | **进入二级页时先「顶栏消失、内容顶到系统栏」再跳转**（用户真机反馈）：顶/底栏可见性由容器层 `if (currentRoute in tabRoutes)` 决定——导航瞬间 `currentRoute` 已变为 detail，而 NavHost 过渡动画期间**退出的 tab 页仍在绘制**，它的栏立刻消失、`innerPadding` 同时塌缩到 0 → 内容瞬时越过系统栏，随后详情页才滑入 | **R-CHROME 结构改造**：栏归路由自身所有。新增 `TabScaffold(currentTab, onSelectTab, content)`，每个 tab 路由包一层（含顶栏动态标题 + 底部 NavigationBar）；详情路由自带内层 Scaffold；根 `NavHost` 直接作为根、不再套容器 Scaffold。路由切换不再影响其它路由的布局，退出动画期间内边距不塌缩；对位 iOS（push 时详情页滑入覆盖整屏、tab 栏随 tab 页一起退场） |
| A22 | **系统栏图标看不清**（用户真机反馈）：应用是**固定深色主题**（InkBg/InkBar），但 `enableEdgeToEdge()` 默认用 `SystemBarStyle.auto(...)`，会按**系统**明暗设置决定栏底与图标明暗。真机系统 `cmd uimode night` = **no（浅色模式）** → 给出**深色图标**，落在 #10182C 顶栏上几乎不可见；浅色模式下的导航栏还会套白色 scrim，与深色 UI 冲突 | **R-SYSTEMBAR**：`enableEdgeToEdge(statusBarStyle = SystemBarStyle.dark(Color.TRANSPARENT), navigationBarStyle = SystemBarStyle.dark(Color.TRANSPARENT))` 固定为「深色栏底 + 浅色图标」，与固定深色主题匹配、与系统设置解耦；`styles.xml` 同步 `android:windowLightStatusBar=false` |

> 教训记录：`emitNode` 的 modifier 拼接曾有 3 处各自实现（modChain / 裸 join / 组件分支），只有 modChain 做了空串过滤与前缀处理。**新增拼接点必须复用 modChain 语义**，否则又会出现「`.clickable` 前导点」这类只在真机编译才暴露的产物缺陷（`vue-tsc` 与单测都拦不住）。
>
> 结构教训（A21）：**路由级 chrome（顶/底栏）不要放在 NavHost 之外、按 `currentRoute` 开关**——过渡动画期间退出页仍在绘制，任何"按当前路由切换外层布局"的写法都会让退出页布局跳变。chrome 应随其所属路由一起进入/退出组合。
>
> 契约教训（A23/A24/A25）：**「页面根」是视口契约的三个面** —— 背景铺满（含安全区）、内容溢出可滚动、页面级 chrome（标题/返回）自带。只要一端按「固定尺寸画布」实现、另一端按「Web body」实现，两端就会持续出现同类差异；本次统一按 Web 语义（body 滚动 + 背景铺满 + 页面自带标题）对齐。
>
> 启发式警告（A24）：用「按钮数 × 行高 > 阈值」猜内容是否超高这种做法，覆盖不到非按钮型长内容，还会误导使用者以为框架支持滚动。**布局能力应由结构保证，不由内容猜测决定**。
>
> 主题教训（A22）：**固定配色主题必须同时固定系统栏样式**。固定深色 UI + `SystemBarStyle.auto`（跟随系统明暗）在浅色系统下必然产生深色图标 → 不可读；系统栏样式应与主题一起被视为"应用身份"的一部分，而非交给系统设置决定。
